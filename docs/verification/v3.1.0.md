# v3.1.0 verification

## Backend and CLI
- `make lint`, `make test`, and static Go build pass.
- Local-session watcher regression reproduced before the v3.0.7 fix; tests
  prove local saves preserve the runner and external CLI replacement triggers reload.
- Wrong-key regression reproduced before the credential fix; encrypted session
  remains recoverable with its original key afterwards.
- Tests cover persistent key reuse, 0600 permissions, key-write failure,
  empty-key rejection, and refusing ownership changes through symlinks.
- Restart command tests cover root/system, sudo/system, per-user service,
  and rejection of unsupported arguments without restarting anything.
- Document shortcut filter matches the document count category (text and PDF).

## Browser checks
Headless Chromium against an isolated local tDocs server and test database.
No production Telegram sign-in or production mutation was performed.

- Light and dark screenshots inspected at 320, 768, 1024, 1440, and 1693px.
- Document scroll width does not exceed viewport width at all ten combinations.
- Header upload and rail drop target each open the native file chooser.
- New Folder submits successfully and the folder appears in the dashboard.
- Documents opens the real document filter; Images, Videos, and Music open
  their existing media libraries.
- Shared Links opens the existing share manager.
- Account menu opens and closes with Escape.
- Telegram setup opens and closes with Escape without sending a sign-in code.
- Storage Manage opens Sync Center; Recent Activity View All opens settings.
- Mobile drawer opens and closes with Escape, keeping aria-expanded correct.
- Category shortcuts activate using keyboard Enter.
- Simulated stats failure shows an explicit error and unavailable storage,
  not invented zero values; Try Again restores the actual stats.
- Empty library and a created-folder state inspected.
- No uncaught JavaScript errors during the successful click-through.
- Fixed an existing login inline-script syntax error discovered by the browser;
  its regression test is part of CI and release validation.

## Production evidence and rollout boundary
Read-only SSH inspection found v3.0.6, a stopped MTProto runner despite an active
web service, and a root-owned 0600 key with a tdocs-owned database. These findings
motivated the watcher and key-ownership fixes. The production installation was
not upgraded during this verification. Live OTP/2FA success still requires the
account owner after installing the new release and repairing existing ownership.
