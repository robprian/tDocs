### Added
- `tdocs restart` for the installed systemd service, and `tdocs restart --user`
  for per-user services. Pairing and files are preserved.
- Reference-led dashboard with compact metrics, file-category shortcuts,
  upload panel, and real recent activity. Light/dark and mobile layouts retained.

### Fixed
- Root CLI login now sets key ownership to match the database, so the service
  can read the same encryption key. This addresses CLI/web pairing differences
  caused by root-owned key files on service installations.
- New keys must be persisted successfully before authentication proceeds;
  empty/unreadable keys fail explicitly and are never silently replaced.
- A wrong encryption key no longer deletes a saved Telegram session.
- Session updates use conditional writes to preserve newer CLI/web sessions.
- Fixed login-page inline JavaScript parsing and Escape handling for setup dialogs.

### Upgrading a service installation
Install the package over the existing version. Keep the database and original
encryption key. If the key was created by root, run the upgraded
`sudo tdocs login` using the same configuration/data directory as the service;
it repairs key ownership to match the database. Then run `tdocs restart`.
The web page refreshes verified Telegram status automatically.

If pairing is still required, authenticate once in either the CLI or web setup.
Never delete or rotate the key to troubleshoot an otherwise valid session.
