## tDocs v3.1.4

### Fixed

- **Service stays down after `tdocs update` (deb):** the old package's `prerm` ran `systemctl disable --now tdocs.service` on every upgrade, and the updater only checked `is-active` *after* apt had already stopped the service — so it printed "not running, no restart needed" while leaving a previously running service stopped *and* disabled. The updater now captures the service state (active + enabled) *before* the install and restores exactly that state afterwards; the `.deb` `prerm` no longer stops the service on upgrade (only on real removal), and `postinst` re-enables + restarts the service on upgrade of an already-configured install — which also self-heals the v3.1.3 → v3.1.4 transition, where the old updater binary is still the one running.
- If your service is currently down after the v3.1.3 update, recover it once with: `sudo systemctl enable --now tdocs` (then `systemctl status tdocs` should show it active again).
