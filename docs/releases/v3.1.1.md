### Fixed
- Upload errors now explain nginx request limits instead of showing an HTML
  error page. A proxy 413 stops immediately rather than retrying the same body.
- Documented the bounded `client_max_body_size 16m` setting needed for tDocs'
  5 MB upload chunks. This applies to all file types; it is not an image-only limit.
- Added upload-flow coverage for JPEG, WebP, JSON, PDF, MP4, MP3, ZIP, and
  unknown binary files, including multi-chunk byte ordering and content hashes.

### Changed
- More compact sidebar: 224px desktop width, 18px navigation icons, 13px text,
  tighter spacing, and a 248px mobile drawer. Buttons retain 44px touch targets,
  keyboard focus, and both themes.

### Deployment
If nginx still returns 413, add `client_max_body_size 16m;` inside the tDocs
HTTPS server block, run `sudo nginx -t`, and gracefully reload nginx.
Keep the application body/file limits enabled. Large files are split into chunks,
so the proxy limit need not match the entire file size.
