## tDocs v3.2.0

### Added

- **Download folder as ZIP:** every folder card and folder row now has a Download ZIP button. The archive streams entry by entry (no whole-folder buffering), includes subfolders recursively, and names entries relative to the zipped folder. Files that fail mid-archive are skipped and logged; the download itself keeps going.
- **Tags:** files can be labelled from the Drive card/row actions (Add tag). Tags are normalized (lowercase, spaces become dashes, only letters, digits, dash and underscore, max 32 chars). A tag filter in the Drive toolbar lists every tag with its file count, and `GET /api/files?tag=` filters server-side within the current folder.
- **File Requests:** a new File Requests page lets the admin create public upload links (name, target folder, optional expiry). Anyone with the link opens `/r/<token>` and uploads without signing in — no account, no password prompt. Expired links return 410, unknown tokens 404, and an upload session minted for one token cannot post through another token's link (403).
- **Scheduled mirror backup:** Sync Center gains a schedule form (enabled + interval in hours, 1–168, default 24h). When due, the server runs the same per-account backup pass used by Backup Now and stamps the last-run time. Mirror covers Telegram files only; disk files are skipped and reported as such.
- **Local disk storage backend:** Settings gains a storage backend selector (Telegram channel or local disk) plus a disk path field. The choice affects new uploads only — existing files keep their backend, so nothing already stored is orphaned. Disk uploads stage under `<root>/.staging/<session>` and land in `<root>/objects/<file-id>`; the root defaults to `<database-dir>/files` when no path is set. Disk files stream with Range support, but have no version history (same-name upload replaces the record and the bytes) and are not mirrored or snapshotted.
- **Dashboard users:** Settings gains a Users section. Additional logins can be created with role `viewer` or `admin`; the login form takes an optional username (empty still means the admin password). Viewers can browse, preview and download but every mutation returns 403, and viewer sessions are never treated as superuser. API tokens keep their existing admin-level behavior.
- **Send file to Telegram chat:** every file card/row gains a Send to Telegram action. It stages the file once (Telegram download or disk read) and re-uploads it to the target chat with `MessagesSendMedia`. `@username` is the reliable target form; a bare numeric user id only works when Telegram can resolve it without an access hash, so prefer usernames.

### Changed

- **Upload core shared:** dashboard uploads and public file-request uploads now run through the same session/chunk/complete code, so a mid-upload settings change cannot reroute chunks — each session pins its storage kind at init.
- **Login audit:** login audit entries now record the username when a dashboard user signs in, instead of always saying `admin`.
- **Static asset versions bumped** (`style.css?v=31`, `app.js?v=24`) so browsers pick up the new dashboard.

### Known limitations

- S3 is not included in this release: the disk backend covers the "storage besides Telegram" request for now; S3 would need credentials plus an SDK and can follow later.
- Mirror and snapshots cover Telegram files only by design (message IDs are Telegram-specific).
- Telegram send cannot copy a message server-side between arbitrary peers; it always re-uploads the bytes, so sending a very large file takes upload time again.
- The pre-existing `TestPrepareKeyFileRejectsSymlinks` failure in `internal/app` (present on v3.1.5 too, unrelated to this release) is not fixed here.
